# GAPS_XenoWarrior Definition of Done

A backlog item is Done only when all applicable conditions below are satisfied.

## Code

- Code is complete and stored in the correct repository location.
- Code runs successfully on the Project Owner's Windows environment.
- No known blocking error remains.
- Dependencies are documented.
- Meaningful errors produce clear messages.
- Exit codes support automation where applicable.

## Validation

- Acceptance criteria are tested.
- Expected positive behavior passes.
- At least one relevant failure condition is tested.
- Generated reports are reviewed.
- No placeholder or empty file is counted as complete.

## Repository

- Files are committed locally.
- Changes are pushed to GitHub.
- Folder and file names follow repository standards.
- Generated outputs record compiler or tool versions where applicable.
- Approved files are never silently overwritten.

## Documentation

- Usage instructions are present.
- Inputs and outputs are identified.
- Known limitations are recorded.
- Related backlog and sprint artifacts are updated.

## Asset Production

- Asset has a valid build request.
- Prompt is compiler-generated.
- Reference roles are declared.
- Output uses approved canvas and format.
- Transparency is validated when required.
- Gold Master promotion requires explicit Project Owner approval.
- Revisions create a new version.

## Product Value

- The increment improves GAPS as a releasable product or moves a game toward release.
- The result can be demonstrated to another person.
- The Product Owner has reviewed and accepted the increment.
